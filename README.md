# Bl3nd — Browser 3D Workspace

Bl3nd is a zero-build, mobile-first browser 3D modeling foundation. The app runs as static HTML/CSS/native JavaScript modules and uses Three.js from a pinned CDN import map.

## First deployment

1. Create a GitHub repository with a `main` branch.
2. Create `.github/workflows/unpack-update.yml` in the GitHub web editor using the exact bootstrap workflow supplied with this release.
3. In repository Settings, set Actions → General → Workflow permissions to **Read and write permissions**. Set Pages → Build and deployment → Source to **GitHub Actions**.
4. Upload `initial-release.zip` into the repository's `uploads/` folder. The action extracts it into the repository root, removes the uploaded ZIP and commits the files. A successful unpack run automatically triggers the GitHub Pages deployment workflow.

The application displays staged startup progress and keeps the exact startup error visible if initialization fails. The progress percentage represents completed initialization phases, not downloaded-byte progress.

The application does not require a build command. Open the GitHub Pages URL after the deployment workflow completes.

## Getting the newest deployed version

When Bl3nd opens, it registers a release-versioned service worker and explicitly checks for updates. Update checks also run when the app becomes visible again or returns to the foreground. A changed worker takes control and reloads the page once. New app-shell files are fetched with HTTP-cache bypass, and page navigation checks GitHub Pages before falling back to the last cached page when offline. This refreshes the newest version that has successfully deployed to Pages; it does not replace a pending or failed GitHub Actions deployment.

For each release, update `APP_RELEASE` in the service-worker registration block in `index.html`. The service-worker cache names derive from that same version automatically.

## Local scene recovery

Bl3nd automatically saves the last committed scene in this browser after a short pause. When you reopen or refresh the app, it restores that scene before creating the starter cube. The recovery includes mesh edits, object transforms, modifiers, visibility, selection, mode, pivot and 3D cursor position. The footer shows checking, ready, pending, saving, saved, restored or unavailable/error status.

Recovery is stored in this browser/device only; it is not synced to GitHub or another device. Active Move/Rotate/Scale, Bevel, Loop Cut and Extrude/Inset previews are not saved until Apply, and the last committed scene is checkpointed before those operations begin. Camera position and undo/redo history are not restored. Export a GLB regularly for a portable copy, and avoid clearing this site's browser storage while relying on local recovery.

- Press `/` when no form field or modal operation owns focus, or tap the **⌕** button in the top bar, to open Command Search.

- Open the **List** tab in the right sidebar on desktop, or tap **List** on the mobile bottom bar. The Explorer shows every scene object with its name, active/selected state and face count; use the arrow to expand an object and its Faces list.
- Tap an object name to select it. Desktop `Shift`+click and the mobile **Multi** toggle add/remove objects from the list selection.
- Expand an object's **Faces** group to see numbered faces and their vertex counts. Selecting a face from Object Mode automatically activates that mesh and enters Edit Mode; selecting another face in Edit Mode updates the face selection. ### Safe topology repair

In Edit Mode, **Repair Safe Issues** removes malformed faces and duplicate faces, reorients independently orientable manifold components, and compacts unused vertices. Its result explicitly reports the repair policy plus the source face IDs and directed edge uses for every preserved non-manifold edge. Components that touch a non-manifold fan are not reoriented across that ambiguity; contradictory/non-orientable components are also preserved and reported by their face IDs. Non-planar faces and self-intersections are never altered by this repair. This avoids deleting faces or inventing a sheet split when the intended surface is ambiguous. Use **Validate Mesh** before and after repair to inspect the remaining issues.

### Extrude and Inset

In Face Select mode, select one face, one connected planar region or multiple disconnected planar islands and press `E` or `I` (or use the Edit Mesh panel). Both operations preview from the immutable source mesh. Drag vertically to adjust, type a numeric value, use arrow keys to nudge, press `Enter` to commit one undo step, or `Esc` to restore the original. Every selected island must be connected, consistently wound, coplanar and have one simple boundary; islands must not share vertices. Extrude derives a separate Newell normal for every island, so concave and arbitrarily rotated planar regions move along their own correct world-space directions. All islands use the same signed Extrude distance. Inset offsets each island boundary inward by the same fraction of its own shortest boundary edge, so the actual world-space offsets may differ. Both operations consume `HalfEdgeMesh.analyzeFaceRegion()` through the safe selected-region partitioner, which rejects holes, branching/touching boundaries and shared-vertex islands. Candidate geometry is built privately, checked for final topology and triangulation, then committed atomically. Positive and negative Extrude distances are supported. Shared corners use miter intersections, and original internal face edges are retained in each inset region. Simple concave regions are supported when every offset remains inside and simple. Connected non-planar face groups (such as several adjacent sides of a cube), holes/multiple boundary loops, inconsistent winding, excessive miters, self-intersections and offsets that collapse/fold a face reject without changing the source. The Inset amount is a fraction of each island's shortest boundary edge; the actual average offset is shown during preview. This is conservative planar-region Extrude/Inset, not Blender's full BMesh parity.

### Bevel

**Face Bevel:** In Face Select mode, press `Ctrl+B` or choose **Bevel**. Region mode raises one connected planar region and keeps its internal seams welded. When the selection contains multiple separate planar islands, Bl3nd automatically starts **Multi-Region** mode: each island is beveled by the same validated shared-region operation, with its own boundary and plane, in one preview/commit transaction. Islands must not share vertices. Press `I` or the mobile mode button to switch to **Individual Faces**, which creates a separate panel for each selected polygon; when all per-face settings still match, the mode button can switch back to Multi-Region. For either shared mode, use 1–8 transition segments, a Profile (`0` concave, `0.50` rounded, `1` convex) and independent width/height factors from 0.01–0.95. Press `H` to switch the active drag/numeric parameter; on mobile use Height +/- and Edit Width/Height. Individual Faces keeps a separate settings record for each selected face: use PageUp/PageDown on desktop or the mobile previous/next face controls, then set that face's width, height, segments and profile without changing the other selected faces. The operation is rebuilt from the immutable source and validated as one transaction; `Enter` applies one undo step and `Esc`/right-click restores everything. Every planar Face Bevel perimeter segment is stored as the same pair of triangles used by the viewport renderer, rather than as a quad. This preserves valid editable wall faces when the raised cap is rotated later, including segmented and Individual Faces bevels. A single connected non-planar selection may enter Continuous Surface mode for a small, smooth, one-boundary patch; other connected non-planar selections use Individual Faces when every polygon is itself planar and safely bevelable. Adjacent selected faces in Individual Faces mode become separate raised panels with a groove at their shared base edge; this is not one smooth continuous curved transition. Shared-vertex-only islands, holes, excessive miters, invalid topology, folded walls and unsupported candidates reject without source mutation. This is not full Blender Face Bevel parity.

For Edge and Face Bevel, drag horizontally to adjust the active amount and use arrow keys for small adjustments. Hold `Shift` for precision. Use `+`/`-` to change segments and `[`/`]` to change profile; hold `Shift` with bracket keys for 0.01 profile steps. For Face Bevel, press `H` to switch width/height; press `I` to switch Region/Multi-Region/Continuous Surface and Individual Faces where a validated shared mode exists; in Individual mode use PageUp/PageDown on desktop or the mobile previous/next face controls to choose which selected face receives parameter edits. Each face stores its own width, height, segments and profile. The mobile pad includes Height +/- and Edit Width/Height controls. After any mesh modal operation finishes, click selection is restored so the next touch drag can orbit the viewport immediately.

Select one edge in Edge Select mode on a closed manifold mesh. The single-edge template is limited to an edge whose two endpoints each have exactly three incident faces, with all four affected faces simple, planar and convex. It replaces the selected edge with a bevel strip and selects its new perimeter.

Connected bevel supports exactly two adjacent edges sharing one closed, tri-valent corner, or one simple path of three to eight consecutive selected edges. The two-edge case intersects offset lines in the common face, creates one shared miter edge and adds two joined bevel strips. Longer chains create one shared-face miter at each internal vertex and close both terminal ends with fan-aware cap patches when needed. Both endpoints and internal junctions may have closed valence-three, -four, -five or -six fans. The ordered opposite fan arc is trimmed at every non-selected radial edge. Valence-four junctions receive one triangular patch; valence-five/six junctions receive center-fanned triangle patches, with one uniquely oriented outer boundary and individually planar triangles. The fan boundary must be simple and convex in its stable projection. Mixed-valence chain regressions cover repeated cap patches, reversed path order, rotated geometry, all 1–8 segment counts and zero-boundary topology. If any chain vertex has valence five or six, profile amplitude is conservatively scaled to 25% to avoid foldovers; the modal reports this limit only when using multiple segments. The exhaustive cube regressions cover all 360 simple tri-valent paths of four through seven edges, and a segmented eight-edge path passes on a closed pentagonal prism. Cycles, branches, mixed connected/disconnected selections, valence above six at either endpoint or internal junction, overlapping cap regions and ambiguous miter intersections are rejected before source mutation. You can also select two to four separate two-edge pairs and process their miter junctions in one transaction when their affected face neighborhoods are disjoint. Alternatively, select up to eight pairwise-disjoint single edges to bevel independent neighborhoods together. The amount is a normalized factor of the safe maximum (45% of the shortest neighboring edge), not a world-unit distance.

Bevel supports **1–8 segments** across each accepted single-edge, connected pair/chain, and disconnected-edge combination. One segment keeps the original strip topology. With multiple segments, the strip is divided into intermediate rows and triangulated per segment; shared miter rows reuse the same vertices so adjacent strips stay connected. The **Profile** control shapes the intermediate cross-section points inside the terminal cap planes: `0` is concave, `0.50` is the default rounded profile, and `1` is convex. Profile shaping is active with two or more segments; the shared miter seam itself stays straight. Candidate topology and triangulation are validated before any source replacement.

Press **Ctrl+B** or choose **Bevel** in the Edit Mesh panel. Drag horizontally, hold `Shift` for width precision, use arrow keys to nudge width, or type an amount from `0.01` to `0.95`. Press `+`/`-` to change segments and `[`/`]` to change profile; Shift with the bracket keys makes fine `0.01` profile adjustments. On mobile, use the on-screen segment and profile +/- rows. `Enter` commits one undoable operation; `Esc` or right-click restores the original mesh. Every preview is rebuilt from the original source, and the complete candidate is topology-validated before commit. Boundary edges, non-manifold or inconsistently wound meshes, existing topology warnings, non-planar/concave faces, fans above valence six, ambiguous miter intersections and excessive miters are rejected without mutation. Chains longer than eight selected edges, branches, cycles, mixed connected/disconnected selections, internal junctions above valence six and open-boundary bevels remain unsupported.

### Loop Cut

Select exactly one edge in Edge Select mode, then press **Ctrl+R** or use **Loop Cut** in the Edit Mesh panel. The operation follows the quad-opposite edge loop and previews 1–8 evenly spaced cuts, sharing an interpolated vertex per cut and crossed edge. Drag horizontally to slide the cut group; hold `Shift` for fine movement, use arrow keys for small nudges, or type a group offset between `0` and `1`. Use the mouse wheel or `+` / `-` to change the number of cuts. `Enter` commits one undoable operation; `Esc` or right-click restores the original mesh. Mobile users can drag, enter an offset, or use the on-screen cut-count controls. Each crossed quad is split into `cuts + 1` quads and all new cut edges remain selected. It accepts consistently wound, convex, planar quad strips and can cross a closed extraordinary all-quad pole only when the two outgoing edges form the same unique reciprocal near-antiparallel pair used by Edge Ring selection. Ambiguous/tied pairings, open extraordinary or mixed-face fans, non-manifold edges, concave/non-planar quads and inconsistent winding reject before mutation. N-gons, multiple distinct seed loops and Blender-equivalent edge sliding remain unsupported.

### Seam-welded Mirror

The Mirror modifier reflects an indexed half-mesh across the selected **X**, **Y** or **Z** plane through the object origin. Its **Merge Distance** is measured in object-local units (default `0.001`, adjustable from `0` to `1`). Source vertices within that distance of the center plane are snapped to the plane in the evaluated copy, and their reflected counterparts reuse the same vertex indices. The reflected triangles reverse winding so their normals face outward, and faces already on the center plane are not duplicated. The editable source mesh is never modified. Start with only one side of the model: Mirror does not automatically bisect/delete the opposite half, move the plane, or weld duplicate vertices away from the mirror seam. On Android, open **More → Mods**, add **Mirror**, choose the axis and adjust **Merge Distance**.

### Modifier-aware Edit Mode selection visibility
When at least one non-destructive modifier is enabled and evaluated, Edit Mode keeps editing the original source cage while the viewport displays the evaluated result. v0.1.83 makes the selected source elements visible over that result: selected faces use a stronger amber fill and bright boundary, selected edges draw through the shell, and selected vertices receive a dark halo with a larger amber center. Unselected cage edges remain depth-tested, so the entire hidden wireframe does not clutter the view. Turning off/removing the last active modifier restores ordinary depth-based selection display. This changes only the visual overlay; it does not modify topology, picking rules, modifier output or selection state.

### Solidify shell thickness

The Solidify modifier builds an inner and outer shell from a triangulated surface and closes open boundary loops with rim walls. **Thickness** is measured in object-local units. **Inside** keeps the original surface in place and grows the shell inward; **Center** distributes the thickness equally to both sides; **Outside** keeps the original inner-facing surface in place and grows outward. Shared vertices use area-weighted surface normals, and closed components are oriented outward in the evaluated copy. The editable base mesh is never changed. The worker rejects non-manifold edges, inconsistent winding, disconnected/branching vertex fans, degenerate faces and local offset triangles that fold or collapse. This is a conservative first-pass shell generator, not a global self-intersection solver: very thick shells, tight concavities, nearby surfaces and sharp-corner preservation are not fully handled. On Android, open **More → Mods**, add **Solidify**, edit Thickness and choose Inside / Center / Outside.

### Catmull–Clark subdivision

The Subdivision modifier now smooths the editable polygon cage with Catmull–Clark rules rather than only splitting rendered triangles. Add it from the Modifiers panel. Its card shows three large **LEVEL 1**, **LEVEL 2** and **LEVEL 3** buttons; the selected level is highlighted and repeated in the card header. On Android, tap **More → Mods** to open the modifier panel.  Quads and n-gons are divided into shared quads; manifold interior vertices use the Catmull–Clark vertex rule and open boundaries use the standard boundary rule. Non-manifold edges, disconnected vertex fans and ambiguous boundary fans reject the preview without replacing the current evaluated mesh. Higher levels grow geometry quickly, so the app caps this control at three levels and rejects a step that would exceed the face safety budget. This is a first Catmull–Clark increment, not full Blender modifier parity.
